# 接口对接说明（HTTP 适配层）

> 契约版本：`1.0.0`（沿用原前后端契约，未改业务字段/枚举/错误码）
> 适用实现：本目录 `server.py` + `backend/` + Vue3 单页 `index.html`
> 说明：原契约只给接口编号与语义，未规定 HTTP 路径/传输细节（T2 未确认）。
> 本次为实现“可运行的最终结果”，在**不改变 14 个接口语义与字段**的前提下，定义如下
> HTTP 绑定；路径与请求头属于传输适配，不是新的业务接口。

## 1. 基础约定

| 项 | 约定 |
|---|---|
| 页面与 API | 同一源：`http://127.0.0.1:8000` |
| API 前缀 | `/api` |
| 请求体 | `POST` 一律 `application/json; charset=utf-8`，body 就是该接口的 `payload` 对象 |
| 响应体 | 严格四字段统一信封（见 §2），无第二套格式 |
| 会话 | `X-Session-Handle: <opaque>`；只放 sessionStorage，不写 URL/DOM/日志 |
| 幂等 | `Idempotency-Key: <8-128 位 A-Z a-z 0-9 . _ : ->`；必需接口见各节 |
| 追溯 | 服务端生成 `trace_id`（32 位小写十六进制），前端展示/复制 |
| 时间 | UTC ISO-8601：`YYYY-MM-DDTHH:MM:SSZ`（T12 参考口径） |
| 周期 | `YYYY-MM` 或 `YYYY-Www`（ISO 周，周一起始） |
| 单位 | 重量字段 `*_kg`，固定 kg；计数 `count`；无任何人次字段 |
| 坐标 | 上行仅 `raw_lat/raw_lng`；下行仅 `coarse_lat/coarse_lng`；审图号缺失不下发点位 |
| 枚举 | 服务端大写字符串；标签由 ADM-01 下发，前端缺失时回退显示 code |

## 2. 统一响应与错误

### 2.1 信封

```json
{
  "code": "OK",
  "message": "查询成功",
  "data": {},
  "trace_id": "0123456789abcdef0123456789abcdef"
}
```

- 成功：`code="OK"`，`data` 为对象；错误：`data=null`，`code` 为七域错误码之一。
- 前端严格校验四字段；契约外字段/缺字段视为契约形状错误，不继续按猜测渲染。

### 2.2 HTTP 状态码

状态码仅作传输语义；**前端以信封 `code` 为准**，不按 HTTP 状态自行推断业务结论。

| 情况 | HTTP |
|---|---|
| 成功 `OK` | 200 |
| `PARAM_*`（含字段/类型/枚举/分页/周期/校验和/幂等键等） | 400 |
| `AUTH_INVALID` / `AUTH_SESSION_*` / `AUTH_VERIFY_FAILED` | 401 |
| `AUTH_LOCKED` | 423 |
| `AUTH_ACCOUNT_EXISTS` | 409 |
| `AUTH_CREDENTIAL_TOO_WEAK` | 400 |
| `PERM_*` | 403 |
| `STATE_*` | 409 |
| `RATE_LIMITED` | 429 |
| `DEP_EXTERNAL_UNAVAILABLE` | 503 |
| `INTERNAL_ERROR` | 500 |
| 未知 API 路径 | 404（`PARAM_UNKNOWN_API`） |
| 已知路径错误方法 | 405（`PARAM_UNKNOWN_API`） |
| 请求体过大 / JSON 非法 | 413 / 400 |

### 2.3 前端固定行为

| 域 | 行为 |
|---|---|
| `PARAM_*` | 展示 message + trace_id，修正表单/参数；不盲目重试 |
| `AUTH_*` | 清理本地凭证回匿名态（登录页/会话菜单同步更新） |
| `PERM_*` | 统一拒绝态；不解释资源是否存在，不换号绕过 |
| `STATE_*` | 提供“重新拉取状态”，按最新后端状态渲染 |
| `RATE_*` / `DEP_*` / `INTERNAL_*` | 统一降级提示，保留 trace_id，可稍后重试 |
| 未知 code | 按 INTERNAL 降级，不冒充业务错误 |

## 4. 逐接口字段

### 4.1 AUTH-01 注册

`POST /api/auth/register`；无会话。body：

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| `account_id` | string | 是 | 4–32 位字母/数字/下划线 |
| `credential` | string | 是 | 8–128 位，至少含字母+数字，不能首尾空白 |
| `verify_token` | string | 是 | 6 位数字；本地演示用 `tools/issue_verify_token.py` |
| `agreement_accepted` | boolean | 是 | 必须为 `true` |

响应 `data`：`account_id:string`、`account_status:"ACTIVE"`、`default_role:"R1"`。
主要错误：`PARAM_*`、`AUTH_CREDENTIAL_TOO_WEAK`、`AUTH_VERIFY_FAILED`、`AUTH_ACCOUNT_EXISTS`、`RATE_LIMITED`、`DEP_EXTERNAL_UNAVAILABLE`。
状态反馈：成功显示账号/状态/默认角色；注册不返回会话，不自动登录。

### 4.2 AUTH-02 登录

`POST /api/auth/login`；body：

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| `account_id` | string | 是 | 4–32 位字母/数字/下划线 |
| `credential` | string | 是 | 1–128 位；登录不校验强度 |
| `device_tag` | string | 是 | 1–64 位，无控制字符；前端自动生成 |
| `second_factor` | string | 否 | 1–32 位；T4 未确认，后端不实现、不记录 |

响应 `data`：`session_handle:string`、`expires_at:string`、`account_profile:{account_id,account_status,roles[]}`、`permission_summary:{roles[],permissions[]}`。
主要错误：`AUTH_INVALID`（统一失败，不区分账号存在性）、`AUTH_LOCKED`、`RATE_LIMITED`、`PARAM_*`。
状态反馈：成功保存会话并跳转；失败清凭证回匿名态。

### 4.3 AUTH-03 登出

`POST /api/auth/logout`；需 `X-Session-Handle`；body：`{"scope":"CURRENT"|"ALL"}`。
响应 `data`：`{"revoked":true}`。过期/未知/已注销句柄按契约返回一致成功语义。
主要错误：`PARAM_INVALID_ENUM`、`AUTH_SESSION_REQUIRED/INVALID`、`DEP_*`、`INTERNAL_*`。
状态反馈：成功清凭证；DEP/INTERNAL 时保留会话并明确提供“仅清理本地凭证”。

### 4.4 AUTH-04 会话态

`GET /api/auth/session`；无 query/body；需 `X-Session-Handle`。
响应 `data`：`session_status:"ACTIVE"`、`account_profile`、`permission_summary`、`expires_at`。
主要错误：`AUTH_SESSION_REQUIRED/INVALID/EXPIRED/REVOKED`。
状态反馈：启动恢复会话；AUTH_* 清理凭证；DEP/INTERNAL 不伪造登录态。

### 4.5 FILE-01 取上传凭证

`POST /api/media/tickets`；需会话；可选幂等键。body：

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| `media_type` | string | 是 | `IMAGE_JPEG` / `IMAGE_PNG` / `VIDEO_MP4` |
| `size_bytes` | integer | 是 | ≥1；JPEG/PNG ≤10MB，MP4 ≤100MB |
| `checksum` | string | 是 | 64 位十六进制 SHA-256 |

响应 `data`：`upload_ticket:string`（仅内存持有，前端不渲染）、`media_ref:string`、`expires_at:string`。
主要错误：`PARAM_INVALID_MEDIA_TYPE`、`PARAM_MEDIA_SIZE_EXCEEDED`、`PARAM_INVALID_CHECKSUM`、`DEP_EXTERNAL_UNAVAILABLE`、`RATE_LIMITED`。
状态反馈：只登记 media_ref；上传完成/访问接口缺失（CR-004），界面不声称已上传。

### 4.6 RPT-01 创建上报

`POST /api/reports`；需会话；**必需** `Idempotency-Key`。body：

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| `raw_lat` | number | 是 | -90–90，有限数；仅上行、不显示 |
| `raw_lng` | number | 是 | -180–180，有限数；仅上行、不显示 |
| `waste_category` | string | 是 | 必须是 ADM-01 `waste_categories` 的 active code |
| `scale_level` | string | 是 | 必须是 ADM-01 `scale_level` 的 active code |
| `media_refs` | string[] | 是 | 1–9 个、去重、属于当前账号、状态可用 |

响应 `data`：`report_id:string`、`report_status:"SUBMITTED"`、可选 `matched_section_id:string`。
主要错误：`PARAM_INVALID_COORDINATE`、`PARAM_INVALID_ENUM`、`PARAM_INVALID_VALUE`、`RATE_LIMITED`、`AUTH_*`。
状态反馈：成功显示 report_id/状态/匹配岸段；立即清除原始坐标；失败保留意图键供同内容重试。

### 4.7 RPT-02 我的上报

`GET /api/reports/mine?page_no=1&page_size=10&report_status=...`；需会话。
query：`page_no` ≥1；`page_size` 1–100；`report_status` 可选，枚举见 ADM-01。
响应 `data`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `items[].report_id` | string | 上报编号 |
| `items[].report_status` | string | 后端枚举 |
| `items[].work_order_status` | string | 后端枚举 |
| `items[].progress_stage` | string | `SUBMITTED/IN_PROGRESS/COMPLETED`，后端计算 |
| `items[].closed` | boolean | 仅 CLOSED 且 cleanup>0 为 true |
| `items[].submitted_at` | string | UTC |
| `total` | integer | 总数 |
| `has_more` | boolean | 分页扩展（CR-008） |

主要错误：`AUTH_*`、`PARAM_INVALID_PAGINATION`、`PARAM_INVALID_ENUM`。
状态反馈：空列表显示空态；`closed/progress_stage` 直接渲染，不本地推导。

### 4.8 MAP-01 热力/岸段

`GET /api/map/sections?period=YYYY-MM&page_no=1&page_size=20&section_id=...`；匿名。
query：`period` 必填；`section_id` 可选；`page_no` ≥1；`page_size` 1–100。
响应 `data`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `sections[].section_id` | string | 岸段编号 |
| `sections[].name` | string | 名称 |
| `sections[].coarse_lat` | number | 粗化纬度 |
| `sections[].coarse_lng` | number | 粗化经度 |
| `sections[].heat_value` | integer | 仅 APPROVED 上报数 |
| `sections[].cleanup_kg_total` | number | 已办结工单 kg 合计 |
| `sections[].responsible_org` | string | 责任单位编号 |
| `map_audit_no` | string \| null | null 时 `sections=[]` |
| `coarsen_degree` | number | 当前粗化度 |
| `total` / `has_more` | integer / boolean | 分页扩展 |

主要错误：`PARAM_INVALID_PERIOD`、`PARAM_INVALID_PAGINATION`、`PARAM_TARGET_NOT_FOUND`。
状态反馈：审图号 null → 合规闸门，不渲染点位/表格；`sections=[]` → 空态；不做原始坐标反推。

### 4.9 WO-01 工单转派

`POST /api/work-orders/dispatch`；R6；**必需**幂等键。body：

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| `work_order_id` | string | 是 | 1–64；必须存在 |
| `target_org_id` | string | 是 | 1–64；必须存在 |

响应 `data`：`work_order_id:string`、`work_order_status:"DISPATCHED"`。
主要错误：`PARAM_TARGET_NOT_FOUND`、`PARAM_TARGET_ORG_NOT_FOUND`、`STATE_INVALID_TRANSITION`、`PERM_*`。
状态反馈：直接展示后端状态；不维护本地列表。

### 4.10 WO-02 工单办结

`POST /api/work-orders/close`；R2/R6；**必需**幂等键。body：

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| `work_order_id` | string | 是 | 1–64；已派单 |
| `cleanup_weight_kg` | number | 是 | >0、≤1,000,000、≤3 位小数 |
| `evidence_refs` | string[] | 是 | 1–9 个、去重、属于当前操作人 |

响应 `data`：`work_order_id`、`work_order_status:"CLOSED"`、`closed:boolean`、`progress_stage:"COMPLETED"`。
主要错误：`PARAM_INVALID_WEIGHT`、`PARAM_INVALID_VALUE`、`STATE_INVALID_TRANSITION`、`PERM_RESOURCE_FORBIDDEN`。
状态反馈：仅后端返回 `closed=true` 才显示已闭环；不本地计算。

### 4.11 REV-01 审核动作

`POST /api/reviews`；R3/R4/R5；**必需**幂等键。body：

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| `target_type` | string | 是 | 当前仅 `REPORT` |
| `target_id` | string | 是 | 1–64；目标存在 |
| `review_level` | string | 是 | `LEVEL_1/LEVEL_2/LEVEL_3`，须与角色/流程匹配 |
| `review_result` | string | 是 | `APPROVED/REJECTED/RETURNED` |
| `comment` | string | 是 | 0–1000；不通过/退回时非空 |

响应 `data`：`review_status`、`review_record_id`、可选 `next_review_level`。
主要错误：`PERM_ROLE_REQUIRED`、`PERM_SOD_VIOLATION`、`STATE_REVIEW_LEVEL_MISMATCH`、`STATE_INVALID_TRANSITION`、`PARAM_TARGET_NOT_FOUND`。
状态反馈：只展示结果；不本地推进；SoD 冲突统一拒绝。

### 4.12 STAT-01 看板/公示

`GET /api/statistics?period=YYYY-MM&section_id=...&metric_keys=cleanup_kg_total&metric_keys=...`；匿名。
- `period` 必填；`section_id` 可选；`metric_keys` 可重复，省略/空表示全部受支持指标。
- 每个 metric：`metric_key`、`value:number`、`unit:"kg"|"count"`、`sample_size:int`、`published:boolean`。
- 响应还有 `leaderboard_enabled:boolean`。
主要错误：`PARAM_INVALID_PERIOD`、`PARAM_UNKNOWN_METRIC_KEY`、`PARAM_TARGET_NOT_FOUND`。
状态反馈：`published=false` 对外不展示数值；榜单关闭显示默认关闭；无榜单数据不排名。

### 4.13 FB-01 办结评价

`POST /api/feedback`；本人；**必需**幂等键。body：

| 字段 | 类型 | 必填 | 校验 |
|---|---|---|---|
| `work_order_id` | string | 是 | 本人上报关联的已办结工单 |
| `rating` | integer | 是 | 1–5 |
| `content` | string | 是 | 1–500 字 |

响应 `data`：`feedback_id:string`。
主要错误：`STATE_CLOSED_REQUIRED`、`STATE_FEEDBACK_DUPLICATE`、`PERM_RESOURCE_FORBIDDEN`、`PARAM_INVALID_RATING`。
状态反馈：成功 Toast feedback_id；无读取接口，不伪造“已评价”状态。

### 4.14 ADM-01 字典与配置

`GET /api/admin/config?config_scope=ALL`；R6/R7。
响应 `data`：`waste_categories[]`、`sections[]`（无坐标）、`status_enums[]`、`coarsen_degree`、`leaderboard_enabled`、`map_audit_no`。
主要错误：`PERM_ROLE_REQUIRED`、`PARAM_INVALID_SCOPE`。
状态反馈：只读；字典不可用时前端回退 code；配置写接口缺失（CR-016）。

## 5. 前端状态与页面行为

| 场景 | 页面行为 |
|---|---|
| 加载中 | 骨架屏/加载按钮；不展示旧数据为新结果 |
| 空数据 | 地图：审图号闸门/空岸段；公示：未发布/空指标；个人中心：空上报；后台：无队列接口的阻塞态 |
| 本地校验失败 | 字段级错误，独立文案，不伪造 `PARAM_*`；后端仍全量重校验 |
| 后端业务错误 | 展示 code/message/trace_id；按域固定行为 |
| 网络/传输失败 | “无法连接后端服务”，提供重试；不伪造业务码 |
| 契约形状错误 | “响应不符合契约”，停止按猜测渲染 |
| AUTH_* | 清理 sessionStorage 会话，回匿名态 |
| STATE_* | “重新拉取状态”，以后端最新值为准 |
| 成功 | Toast + 结果卡；trace_id 可复制 |

页面 ↔ 接口：
- 地图 → MAP-01；公示 → STAT-01；科普/上报/后台字典 → ADM-01（受权限）。
- 登录/注册/会话 → AUTH-01/02/04；登出 → AUTH-03。
- 上报 → FILE-01 + RPT-01；个人中心 → RPT-02 + FB-01。
- 后台审核 → REV-01；工单 → WO-01/WO-02；看板 → STAT-01；字典 → ADM-01。

## 6. 演示与已知契约缺口

本地演示默认配置：
- `map_audit_no = "SAMPLE-ONLY-NOT-A-REAL-AUDIT-NO"`（仅演示；生产必须替换/清除，清除后不下发点位）；
- `leaderboard_enabled=false`；
- `coarsen_degree=0.01`。

已知缺口（未新增接口绕过）：
| 缺口 | 影响 | 处理 |
|---|---|---|
| ADM-01 仅 R6/R7 | R1/R3–R5 无字典；R1 上报表单阻塞 | 回退显示 code / 使用运营演示账号；CR-001 |
| RPT-02 无 `work_order_id` | 评价需手工输入 | 演示辅助可选填入；CR-FE-02 |
| 无审核队列/详情/媒体 | 按编号审核 | 阻塞态 + 演示辅助；CR-FE-03 |
| 无工单列表/详情/组织名称 | 手工编号/组织编号 | 阻塞态 + 演示辅助；CR-FE-04 |
| 无科普内容/答题 | 仅类别展示 | 阻塞态；CR-003/CR-FE-05 |
| 无上传完成/媒体访问 | FILE-01 仅登记 | 明确“未上传”；CR-004 |
| 无榜单数据/历史/趋势 | 仅开关/当前周期 | 不排名、不拼接；CR-002/CR-FE-10 |
| 无通知/账户设置/凭证找回 | 阻塞态 | 保留入口；CR-020/CR-FE-07 |

> 这些是原契约的已知缺口；本实现未为了“看起来完整”而硬编码业务数据或伪造接口。
