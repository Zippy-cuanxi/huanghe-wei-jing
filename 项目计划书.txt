## 1. 项目目标

| 编号 | 目标 | 归属侧重 |
|---|---|---|
| G1 | 构建面向公众的黄河上游岸线垃圾治理宣传与参与平台，形成「拍—派—清—晒」闭环 | 后端主导闭环，前端承载呈现 |
| G2 | 以岸段垃圾监测点位为核心依据生成热力地图，并支持交互式可视化 | 后端计算，前端渲染 |
| G3 | 由纯静态前端扩展为前端／后端／数据存储三层，并引入用户认证 | 两端按 §3 分工 |
| G4 | 支撑内容三审三校、工单转派办结、个人数据归属与分级权限 | 后端独占规则，前端按摘要呈现 |
| G5 | 满足合规：标准地图审图号、点位粗化、清理量公斤口径 | 后端强制，前端正确展示 |
| G6 | 两端可独立实现、接口理解一致、交付物可直接衔接 | 双方共守 §4 |

**非目标**：不承担执法职责；不是保洁调度系统；不面向全流域作宏大泛化表述；不增补模板外额外功能或独立字段；本阶段不产出实现方案、实现代码、联调代码。

## 3. 职责划分

### 3.1 唯一归属原则

| 事项 | 唯一归属 | 另一方明确禁止 |
|---|---|---|
| 视图、交互、布局、加载／空态／拒绝态 | 前端 | 后端不产出渲染结构 |
| 格式级校验与即时反馈 | 前端 | 后端不依赖其结论，须全量重校验 |
| 契约级／业务级校验、状态机、业务规则 | 后端 | 前端不得预判任何业务结论 |
| 分类归属、岸段匹配、AI 初判、热力计入 | 后端 | 前端不得自算 |
| 闭环判定、进度计算、审核与工单流转 | 后端 | 前端不得本地推导或乐观推进 |
| 鉴权裁决、权限即时生效、审计生成 | 后端 | 前端界面裁剪不构成安全边界 |
| 数据权威、坐标粗化、审图号与开关下发 | 后端 | 前端不得硬编码枚举与粗化度 |
| 界面态、凭证安全持有、幂等键生成 | 前端 | 后端不得代为生成或回写为业务事实 |
| 接口契约、字段字典、枚举、错误码 | 双方共守 | 任一方不得单方面变更 |

### 3.3 权限与状态边界

| 状态类别 | 权威方 | 前端可做 | 前端禁止 |
|---|---|---|---|
| 会话态 | 后端 | 安全持有凭证、按状态跳转 | 自判有效性、自行延长有效期 |
| 权限摘要 | 后端 | 裁剪菜单／按钮 | 作鉴权依据、用过期摘要放行 |
| 业务态（上报／工单／审核／评价） | 后端 | 按响应渲染 | 本地推导、缓存为权威 |
| 配置态（枚举／字典／开关／审图号） | 后端 | 启动拉取、内存使用 | 硬编码 |
| 界面态（加载／空态／分页／草稿） | 前端 | 完全自有 | 回写为业务事实 |
| 文件态（上传进度／预览） | 前端 | 展示 | 审核前媒体对外引用 |

角色集沿用 R0 匿名用户、R1 公众注册用户、R2 责任单位操作员、R3／R4／R5 初审／复审／终审员、R6 运营管理员、R7 系统管理员、R8 审计员（该角色集为前序推导值，待确认，不得视为既定业务范围）。三审三校不得由同一人连续两级；系统管理员不兼终审。

## 4. 共享接口约定

### 4.1 契约通则

| 项 | 约定 |
|---|---|
| 通信风格／地址规范／序列化格式／字段命名风格 | 待确认项，两端不得自行假定；下表字段名为语义锚点 |
| 统一响应 | `code`（结果码）、`message`（可直接展示文案）、`data`（业务负载）、`trace_id`（追溯标识） |
| 分页 | 请求 `page_no`／`page_size`（上限由后端定义）；响应 `total`／`items`／`has_more` |
| 幂等 | 所有写接口带 `idempotency_key`（前端生成），重复请求结果一致 |
| 单位 | 重量字段一律 `*_kg`，固定 kg；禁止人次字段 |
| 坐标 | 上行 `raw_lat`／`raw_lng`；下行仅 `coarse_lat`／`coarse_lng`，粗化度随 `coarsen_degree` 下发 |
| 时间 | `*_at` 后缀；格式与时区待确认 |
| 状态 | 大写枚举字符串，由字典接口下发，前端不硬编码业务含义 |
| 错误码域 | `PARAM_*`／`AUTH_*`／`PERM_*`／`STATE_*`／`RATE_*`／`DEP_*`／`INTERNAL_*` |
| 版本 | `contract_version`；字段只增不删、枚举只追加，变更须双方同步 |

### 4.2 关键接口清单

| 编号 | 能力 | 请求字段（关键） | 响应字段（关键） | 权限 | 约束 |
|---|---|---|---|---|---|
| AUTH-01 | 注册 | `account_id`, `credential`, `verify_token`, `agreement_accepted` | `account_id`, `account_status`, `default_role` | 匿名 | 唯一性与强度校验在后端；凭证不回显、不入日志 |
| AUTH-02 | 登录 | `account_id`, `credential`, `device_tag`, `second_factor?` | `session_handle`, `expires_at`, `account_profile`, `permission_summary` | 匿名 | 失败统一 `AUTH_INVALID`，不泄露账号存在性 |
| AUTH-03 | 登出 | `session_handle`, `scope`(CURRENT/ALL) | `revoked` | 已认证 | 幂等；已过期会话返回一致结果；旧凭证必被拒 |
| AUTH-04 | 会话态查询 | `session_handle` | `session_status`, `account_profile`, `permission_summary`, `expires_at` | 已认证 | 界面裁剪唯一依据 |
| FILE-01 | 取上传凭证 | `media_type`, `size_bytes`, `checksum` | `upload_ticket`, `media_ref`, `expires_at` | 已认证 | 限时；审核前不对外 |
| RPT-01 | 创建上报 | `raw_lat`, `raw_lng`, `waste_category`, `scale_level`, `media_refs[]`, `idempotency_key` | `report_id`, `report_status`, `matched_section_id?` | 待确认 | 分类／规模由字典校验；AI 初判后端回填 |
| MAP-01 | 热力与岸段查询 | `section_id?`, `period`, `page_no`, `page_size` | `sections[{section_id, name, coarse_lat, coarse_lng, heat_value, cleanup_kg_total, responsible_org}]`, `map_audit_no`, `coarsen_degree` | 匿名 | 仅粗化坐标；仅审核通过计入热力；审图号缺失不下发点位 |
| RPT-02 | 我的上报与进度 | `page_no`, `page_size`, `report_status?` | `items[{report_id, report_status, work_order_status, progress_stage, closed, submitted_at}]` | 本人 | `closed`／`progress_stage` 全由后端计算 |
| WO-01 | 工单转派 | `work_order_id`, `target_org_id`, `idempotency_key` | `work_order_id`, `work_order_status` | R6 | 状态机合法性后端裁决 |
| WO-02 | 工单办结 | `work_order_id`, `cleanup_weight_kg`, `evidence_refs[]`, `idempotency_key` | `work_order_id`, `work_order_status`, `closed`, `progress_stage` | R2／R6 | 仅 `cleanup_weight_kg>0` 且状态合法才 `closed=true` |
| REV-01 | 审核动作 | `target_type`, `target_id`, `review_level`, `review_result`, `comment`, `idempotency_key` | `review_status`, `next_review_level?`, `review_record_id` | R3／R4／R5 | 后端强制职责分离；可退回 |
| STAT-01 | 看板／公示指标 | `period`, `section_id?`, `metric_keys[]` | `metrics[{metric_key, value, unit, sample_size, published}]`, `leaderboard_enabled` | 公众只读／R6 | 榜单默认关闭且需 `sample_size` 核实 |
| FB-01 | 办结评价 | `work_order_id`, `rating`, `content`, `idempotency_key` | `feedback_id` | 本人 | 仅 `closed=true` 后允许 |
| ADM-01 | 字典与配置 | `config_scope` | `waste_categories[]`, `sections[]`, `status_enums[]`, `coarsen_degree`, `leaderboard_enabled`, `map_audit_no` | R7／R6 | 启动拉取，枚举不硬编码 |

### 4.3 关键字段约束

| 字段 | 生产方 | 消费方 | 强约束 |
|---|---|---|---|
| `raw_lat`／`raw_lng` | 前端 | 后端 | 上行专用，永不下行，不落前端持久缓存 |
| `coarse_lat`／`coarse_lng` | 后端 | 前端 | 下行专用，粗化度随 `coarsen_degree` |
| `heat_value` | 后端 | 前端 | 仅审核通过记录计入 |
| `cleanup_weight_kg` | 前端录入 | 后端校验 | >0 才允许闭环 |
| `closed`／`progress_stage` | 后端 | 前端 | 只读，禁止本地推导 |
| `review_status`／`review_level`／`review_result` | 后端 | 前端 | 仅展示 |
| `permission_summary` | 后端 | 前端 | 仅用于界面裁剪，不作鉴权依据 |
| `session_handle` | 后端 | 前端 | 安全持有，不出现在地址／日志 |
| `map_audit_no` | 后端 | 前端 | 必须展示；缺失则不下发点位 |
| `leaderboard_enabled` | 后端 | 前端 | 默认关闭态 |
| `trace_id` | 后端 | 前端 | 报错时透传，供衔接定位 |

### 4.4 异常归属与固定行为

| 环节 | 前端 | 后端 |
|---|---|---|
| 异常生成 | 不生成业务错误 | 统一 `code`／`message`／`trace_id`，写审计，不返回堆栈与内部字段 |
| 异常呈现 | 码→文案映射、统一错误组件，不吞错、不自造业务错误 | 兜底安全降级，不得绕过鉴权或粗化 |

前端固定行为：`AUTH_*` → 清理凭证回匿名态；`PERM_*` → 拒绝态；`STATE_*` → 重新拉取后端状态；`RATE_*`／`DEP_*`／`INTERNAL_*` → 统一降级提示并保留 `trace_id`。

### 4.5 契约变更规则

契约版本冻结后，任何一方发现字段、枚举、错误码或权限口径需要调整，须提交「契约变更请求」（含原因、影响接口、建议），经双方同步并升版后方可生效；禁止静默修改、禁止单方面扩字段。

## 6. 验收标准

### 6.1 文档级验收

- **职责不重叠**：§3.1 每一项均能指向唯一归属方，无双方同时主张的事项。
- **接口理解一致**：两端交付说明中的字段、枚举、单位、坐标口径、错误码逐项一致。
- **交付物可衔接**：前端字段映射表与后端字段字典可逐接口对照；权威样例与前端桩自测记录可互相印证。

### 6.2 可联调准入

契约版本冻结且字段字典／枚举表双方一致；后端已提供权威响应样例（含成功与各类错误码）；两端各自跑通本侧校验与异常分支，自证无需对方即可完成本侧逻辑。

### 6.3 分组验收

| 验收组 | 必验点 | 通过判据 |
|---|---|---|
| 认证组 | 注册／登录／登出／会话态、锁定策略 | 错误码统一、不泄露账号存在性、登出后旧凭证必被拒 |
| 上报组 | 坐标口径、AI 初判、审核计入、幂等 | 原始坐标仅上行；审核通过才计入热力；重复提交不产生重复记录 |
| 地图／统计组 | 审图号、粗化、榜单、单位 | 下行无原始坐标；单位 kg／吨、无人次字段；榜单默认关闭 |
| 工单组 | 办结闭环、进度一致性 | 仅 `closed=true` 时三段进度走满；重复办结幂等 |
| 审核组 | 三级流转、职责分离、退回 | 职责分离冲突必被拒绝；退回可重走 |
| 权限组 | 角色矩阵逐项 | 界面裁剪与后端裁决一致；越权必被拒且写审计 |

### 6.4 一票否决项

前端自行推导业务状态、下行出现原始坐标、出现人次字段、审图号缺失仍下发点位、权限仅靠界面裁剪、未经双方同步的契约变更 —— 任一项出现即判不通过。
